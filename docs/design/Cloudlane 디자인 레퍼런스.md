# Cloudlane 디자인 레퍼런스 (라이트/다크 목업 분석)

> 업로드된 `Cloudlanelight.html` / `Cloudlanedark.html`을 headless 브라우저로 직접 렌더링해서 추출한 내용이다. 두 파일은 **Tailwind v4 + React로 빌드된 번들(단일 HTML)** 이라 정적으로 열어보면 `id="root"` 하나와 압축된 JS만 보이고, 화면 내용은 전부 JS가 브라우저에서 그려낸다 — 그래서 텍스트 프롬프트나 grep만으로는 이 디자인을 읽어낼 수 없다(사용자가 걱정한 부분이 맞다). 아래는 실제로 실행해서 뽑아낸 값이다.

## 1. 화면 인벤토리

정적 파일이지만 실제로는 클라이언트 라우팅이 있는 5화면짜리 인터랙티브 디자인이다(사이드바 클릭으로 전환 확인함). 다크모드 토글도 실제로 동작한다.

| 화면 | 내용 요약 |
|---|---|
| 대시보드 | 연결된 클라우드 수, 전체 리소스, 이번 달 비용, 서비스 가용성 카드 4개 + 일별 비용 추이 라인차트 + 클라우드별 리소스 비중 + 주요 리소스 테이블 + 최근 알림 2건 + 절감 제안 배너 |
| 리소스 | 리소스 목록 테이블(클라우드/리전/상태/CPU/월 예상비용), 클라우드별 필터 탭(전체/AWS/Google Cloud/Azure) |
| 비용 분석 | 비용 추이 차트, 이번 달 예산 대비 사용률 게이지, 클라우드별 비용 누적 |
| 알림 | 최근 24시간 알림 리스트(심각도/클라우드/리전 태그 + 설명) |
| 설정 | 화면 모드(라이트/다크) 설명 카드, 연결된 클라우드 계정 3개(AWS/GCP/Azure) 목록 |

로고/브랜드 텍스트: **`cloudlane.`** (소문자, 마침표 포함). 워크스페이스명 예시: "Cloudlane Workspace". 전부 데모 데이터이며 화면 하단에 "데모 워크스페이스 · 실제 클라우드에 연결되지 않음" 문구가 고정으로 붙어 있다.

## 2. ⚠️ 확정 문서(기능명세서/화면설계서)와의 불일치

이 디자인의 IA(정보구조)가 지금까지 확정한 문서와 다르다 — 그대로 구현 기준으로 삼기 전에 팀 확인이 필요하다.

| 항목 | 기능명세서/화면설계서(확정) | Cloudlane 디자인(이번 목업) |
|---|---|---|
| 사이드바 메뉴 | 대시보드 / 인벤토리 / 프로비저닝 / 마이페이지 | 대시보드 / 리소스 / 비용 분석 / 알림 / 설정 |
| 프로비저닝 화면 | 핵심 기능(4번) | **없음** |
| 마이페이지 | 계정정보·키관리·보고서 설정(5번) | **없음** (대신 "설정"에 화면모드+연결계정 일부만) |
| 비용 관리 | 화면설계서상 "확장 기능·개발 후순위"(COST-01) | **1군 메뉴로 승격**, 이름도 "비용 분석" |
| 알림 | 사이드바 하단 아이콘(유틸) | **1군 메뉴로 승격**, 별도 화면 |
| 보안 점검(SEC-01) | 확장 기능 | 이 목업엔 아예 없음 |

이 목업은 프로비저닝처럼 "실제 리소스를 만드는" 화면이 빠져 있는 걸 보면, **전체 IA 교체용이라기보다 비주얼 스타일(색·타이포·컴포넌트 룩)을 검토하기 위한 디자인 시안**일 가능성이 높다. 다만 확정은 아니니 아래 중 어느 쪽으로 반영할지 결정이 필요하다.

- (A) 색상·타이포·컴포넌트 스타일만 이 디자인에서 가져오고, 화면 구성(사이드바 메뉴/페이지 목록)은 기존 확정 화면설계서를 그대로 따른다.
- (B) 이 디자인의 IA를 새 기준으로 채택하고, 기능명세서·화면설계서 쪽을 갱신한다(프로비저닝을 어디에 넣을지 등 재설계 필요).

## 3. 디자인 토큰 (실측값)

`getComputedStyle(document.documentElement)`로 뽑은 CSS 커스텀 프로퍼티 중 색상 관련 값만 정리. 라이트/다크 모드가 값 자체가 다른 진짜 테마 전환이다(단순 필터 아님).

| 토큰 | 라이트 | 다크 | 용도(추정) |
|---|---|---|---|
| `--background` | `#f2f6fa` | `#0b1724` | 페이지 배경 |
| `--foreground` | `#162e40` | `#e5edf5` | 기본 텍스트 |
| `--surface` / `--color-popover` | `#fff` | `#142536` | 카드/팝오버 배경 |
| `--muted` | `#edf3f8` | `#203348` | 보조 배경(칩, 서브 섹션) |
| `--muted-foreground` | `#6a7e90` | `#a0b4c7` | 보조 텍스트 |
| `--border` / `--color-border` | `#e7edf2` | `#2a3d50` | 테두리 |
| `--sidebar` | `#102f4b` | `#10283e` | 사이드바 배경(라이트에서도 짙은 네이비 — 사이드바는 항상 다크) |
| `--sidebar-accent` | `#224966` | `#224966` | 사이드바 hover/active |
| `--primary` | `#145d91` | `#77b4e4` | 주요 버튼/강조(모드별로 톤이 바뀜) |
| `--sky` | `#56a5dd` | `#56a5dd` | 차트/포인트 블루 |
| `--aero` | `#77b4e4` | `#77b4e4` | 보조 블루 |
| `--yellow` | `#ecc815` | `#ecc815` | 포인트 옐로(설정 화면 설명에 "블루·옐로 팔레트"라고 명시) |
| `--cta-text` | `#162326` | `#162326` | 버튼 위 텍스트 색(옐로 배경 위 다크 텍스트용으로 추정) |

**폰트**: `Arial, "Malgun Gothic", sans-serif` — 웹폰트(Pretendard 등) 없이 시스템 폰트만 사용하도록 소스에 고정되어 있음(오프라인이라 못 받아온 게 아니라 실제 설계임). 기존 화면설계서 문서 자체의 폰트(Pretendard)와는 다르니, 실제 서비스 폰트를 어느 쪽으로 할지도 확인 필요.

## 4. 완벽 반영을 위한 권장 방법

텍스트 프롬프트만으로 "이 디자인처럼 만들어줘"라고 지시하면 색상·간격을 다시 눈대중으로 추측하게 되어 오차가 생긴다. 아래 순서를 권장한다.

1. **스크린샷을 진실의 원천으로 삼는다** — 5화면 × 라이트/다크 = 10장을 이미 캡처해뒀다(첨부 파일 참고). 프론트엔드 구현 프롬프트에 "이 스크린샷과 픽셀 단위로 맞출 것"이라고 명시하고, 실제 화면 파일과 함께 레포의 `docs/design/` 폴더에 넣어 각 브랜치 작업의 기준 자료로 삼는다.
2. **위 3절 색상 토큰을 그대로 CSS 변수로 이식한다** — 눈대중으로 비슷한 색을 고르지 않고, 이 표의 hex 값을 `:root`/`[data-theme="dark"]`에 그대로 옮겨 쓰면 값 자체는 100% 일치한다.
3. **원본 소스가 있으면 그게 최우선이다** — 이 두 HTML은 빌드 결과물이라 컴포넌트 구조·spacing 스케일까지는 못 읽는다. Figma나 이 목업을 만든 원본 프로젝트(React 소스, Tailwind 설정)가 남아있다면 그걸 받는 게 가장 정확하다. 없다면 스크린샷+토큰이 현실적 최선이다.
4. **2절의 IA 불일치를 먼저 정리한다** — 화면 구조가 안 맞는 채로 스타일만 이식하면 "이 색은 어느 화면에 쓰나"가 계속 애매해진다. 결정 후 다음 프롬프트(프론트엔드 착수)에 반영하겠다.
