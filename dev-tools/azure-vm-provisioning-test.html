Azure VM 프로비저닝 테스트

dev-tools/ — 팀 확정 화면(frontend/)과 별개인 QA/개발용 페이지입니다. docs/01_API_명세서_v1.1.md 10절 API를 실제로 호출해 Azure VM 생성 흐름 전체를 확인합니다.
⚠️ 실제 Azure 구독에 요청을 보냅니다. 3단계에서 "생성 요청 보내기"를 누르면 실제 과금이 발생할 수 있는 VM 생성이 시도됩니다. 인증에 쓰이는 get_current_user_id는 아직 회원가입/로그인이 없어 Authorization: Bearer <user_id>만 파싱하는 임시 구현입니다(정식 스펙 아님).

1 테스트 사용자 준비

회원가입 API가 아직 없어서 POST /api/v1/dev/users(dev 전용, 정식 스펙 아님)로 대체합니다. 이미 user_id가 있으면 바로 입력하고 2단계로 넘어가도 됩니다.

2 Azure credential 등록

POST /api/v1/credentials/azure — Service Principal(tenant_id/client_id/client_secret/ subscription_id)을 서버가 AES-256-GCM으로 암호화해 저장합니다. 이 페이지는 secret을 저장하지 않고 요청 한 번에만 씁니다.

3 Azure VM 생성 요청

POST /api/v1/provisioning/azure/vm — Idempotency-Key는 매 요청 새로 생성되고, X-Action-Confirmed: true는 "생성 요청 보내기" 클릭 자체를 사용자 확인으로 간주합니다.

4 Job 상태 확인

GET /api/v1/provisioning/jobs/{'{job_id}'} 를 3초 간격으로 폴링합니다. 실제 Terraform 실행(백그라운드)이 끝나 success/failed로 종결되면 자동으로 멈춥니다.
현재 상태: -
이 페이지는 backend/app/routers/provisioning.py, credentials.py, dev_tools.py가 실제로 응답하는지 눈으로 확인하기 위한 것입니다. 프로덕션 화면 (frontend/)과 무관하며 배포 대상이 아닙니다.
